# Experiment 01: Comprehensive HTML5 Elements Showcase

## 🎯 Course Outcome Mapping
* **CO2:** Create and build web pages and applications.

## 📋 Objectives Covered
1. **Semantic Web Architecture:** Designed a well-structured web workspace using native HTML5 structural containers instead of legacy division maps.
2. **Standardization Analysis:** Formulated a direct comparison matrix to contrast layout variations between old HTML4 blocks and modern HTML5 specifications.
3. **Advanced Input Components:** Integrated rich client data capture elements including validation limits, calendar objects, color selectors, and slider tools.
4. **Native Multimedia Channels:** Handled internal video and audio stream embedding natively using baseline HTML5 tag protocols without relying on external plugins.
5. **DOM Hierarchy Architecture:** Documented the conceptual Document Object Model rendering tree directly into the interface blueprint.
6. **SEO & Accessibility Compliance:** Applied critical metadata targets, optimized semantic headers, and clear structural labels to support screen-reader engines.

---

## 🛠️ Implemented HTML5 Features Matrix

### 1. Layout & Structure (Semantic tags)
* `<header>` & `<footer>` (Page boundaries)
* `<nav>` (Accessible navigation index paths)
* `<main>` (Core viewport data focus area)
* `<section>` & `<article>` (Categorized data modules)
* `<aside>` (Supplementary sidebar workspace)
* `<figure>` & `<figcaption>` (Media content wrappers)

### 2. Form Interface Elements (`<form>`)
* `<input type="email">` (Natively evaluates email patterns)
* `<input type="date">` (Launches clean system calendars)
* `<input type="color">` (Opens graphic color palettes)
* `<input type="range">` (Provides custom range sliders)
* `<input type="number">` (Enforces strict lower and upper bounds)
* `<datalist>` (Generates smart predictive drop-downs)

### 3. Native Multimedia Controls
* `<video>` (Controls browser MP4 video feeds using customized layout skins)
* `<audio>` (Decodes basic system sound tracks instantly)

### 4. Inline Graphic Progress Metrics
* `<progress>` (Tracks linear progression scales)
* `<meter>` (Visually illustrates threshold metrics)

## 🚀 How to Run this Project Locally

Since this experiment relies entirely on client-side markup, it does not require a backend engine server or runtime packages to load.

### Method 1: Desktop Execution (Fastest)
1. Navigate into the folder tracking these components: `Backend-Development/Experiment_01/`
2. **Double-click** the `index.html` file.
3. Your computer will automatically launch the project inside your default web browser (Chrome, Edge, Firefox, or Safari).

### Method 2: Development Live Server (Recommended)
1. Launch your **VS Code IDE** workspace opened directly to your parent `Backend-Development` folder.
2. Install the **Live Server** plugin extension created by *Ritwick Dey*.
3. Open your `Experiment-01/index.html` file code view panel.
4. Click the **"Go Live"** button anchored along the bottom-right status strip. 
5. The application UI will deploy dynamically using a local development server route address: `http://127.0.0`
